## 2024-12-25 - Dynamic Active State Accessibility
**Learning:** In the `lucid/` app, when a component like `DataCard` acts as an interactive element (e.g., clickable to view details) but its interactivity is dynamically toggled (e.g., disabled in `editMode`), it is insufficient to simply guard the `onClick` handler. All keyboard accessibility semantics (`role="button"`, `tabIndex={0}`, `onKeyDown` handlers for `Enter` and `Space`), as well as visual indicators like `cursor-pointer`, hover effects, and `focus-visible` outlines, must be completely removed when the element is inactive to avoid misleading screen readers and keyboard users.
**Action:** When making non-button elements interactive, ensure that all accessibility and interactive styling attributes are conditionally applied based on the component's active state, and use `e.preventDefault()` for the `Space` key in the `onKeyDown` handler to prevent unintended page scrolling.
