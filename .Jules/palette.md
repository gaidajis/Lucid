## 2024-05-30 - Conditional Keyboard Accessibility for Interactive Divs
**Learning:** When using `div` or `motion.div` as an interactive button (e.g., clicking to view details), it must have `role="button"`, `tabIndex={0}`, an `onKeyDown` handler for 'Enter'/'Space', and `focus-visible` classes for full keyboard and screen reader accessibility. Crucially, if the element's interactivity is dynamic (like disabled in an "edit mode"), these semantics and styles *must* be conditionally removed (`role={undefined}`, `tabIndex={undefined}`, stripping cursor/hover/focus classes). Leaving a `role="button"` or a focus style on an element that no longer responds to clicks creates a frustrating, "broken" experience for keyboard/screen reader users.
**Action:** Always conditionally apply both visual affordances (cursor-pointer, hover, focus rings) AND accessibility semantics (role, tabIndex, onKeyDown) together using ternary operators when a non-semantic element's interactivity state changes.
