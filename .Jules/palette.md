## 2024-05-31 - Conditional Interactivity on DataCards
**Learning:** When using container elements (like `motion.div`) as buttons in mixed-state environments (e.g., normal view vs edit mode), applying generic interactive styles (`cursor-pointer`, `hover:shadow`) unconditionally creates a disjointed UX if the interaction is disabled. Furthermore, adding click handlers without proper accessibility semantics (`role="button"`, `tabIndex`, `onKeyDown`) breaks keyboard navigation.
**Action:** Always conditionally render cursor utilities, hover styles, and accessibility attributes based on the current interactive state. If an element's primary click action is disabled (e.g. during editMode), strip it of pointer cursors, tabIndex, role, and focus-visible outlines to clearly communicate its non-interactive state to all users.
