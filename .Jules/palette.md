## 2024-05-31 - Dynamic Keyboard Accessibility for Clickable Cards
**Learning:** In applications where interactive elements (like data cards) have different interaction modes (e.g., viewing vs. editing), hardcoding accessibility semantics (like `role="button"`, `tabIndex={0}`, and `focus-visible` styles) can lead to a confusing experience if the element becomes non-interactive in certain modes. Applying `role="button"` when the card's main action is disabled or overriden by inner actions (like edit/delete buttons) creates incorrect expectations for screen reader and keyboard users.
**Action:** Always conditionally apply accessibility semantics (`role`, `tabIndex`, `onKeyDown`, and focus-visible styling) to match the element's actual interactable state. If an element's `onClick` is conditionally disabled or overriden by an edit mode, its keyboard accessibility attributes must also be dynamically removed.
