## 2024-05-18 - Keyboard Accessibility and Interactive Element States
**Learning:** Found that non-interactive components acting as buttons (like `motion.div` in `DataCard`) lacked necessary focus styles and keyboard handling. Additionally, we need to completely remove keyboard accessibility semantics (like tabIndex and role) when standard interactive elements transition to a disabled or non-interactive state (such as during an edit mode where clicking the card does nothing, to avoid trapping focus).
**Action:** Implemented a standard pattern: dynamically apply `role="button"`, `tabIndex={0}`, an `onKeyDown` handler (for `Enter` and `Space`), and `focus-visible` utility classes strictly when elements are interactive, conditionally removing them entirely when non-interactive.
