## 2024-06-03 - Keyboard Accessibility on non-button Interactive Elements
**Learning:** When using components like `motion.div` as interactive, clickable elements, `onClick` alone is insufficient. Screen readers and keyboard-only users cannot access them. When these elements toggle between interactive and non-interactive states (e.g. read mode vs edit mode), leaving semantics active in non-interactive states is confusing and breaks expected UX flows.
**Action:** Always pair `onClick` with `role="button"`, `tabIndex={0}`, an `onKeyDown` handler for Enter/Space, and visible focus styles (like `focus-visible:ring-2`). Additionally, conditionally remove these attributes (`role={undefined}`, `tabIndex={undefined}`) and cursor/hover styles when the element is rendered non-interactive, as done in DataCard.tsx.
