## 2024-06-01 - Dynamic Keyboard Accessibility for Interactive Cards
**Learning:** When making non-button elements (like `div` or `motion.div`) interactive (e.g., clicking opens a modal), it's crucial to not just add an `onClick` handler, but also `role="button"`, `tabIndex={0}`, and an `onKeyDown` handler (for `Enter` and `Space`). Furthermore, in apps with dynamic interaction states (like an "edit mode" where the card itself is no longer clickable but contains its own action buttons), these accessibility semantics and focus styles must be conditionally applied or removed to prevent users from focusing or trying to interact with an element that has no active behavior.
**Action:** Always conditionally apply `role`, `tabIndex`, `onKeyDown`, and `focus-visible` styles when building custom interactive components that can enter a disabled or non-interactive state.
