## 2024-05-17 - Keyboard Accessibility for Clickable Containers
**Learning:** In the `lucid` project, high-level interactive elements built using custom components (like `<motion.div>` for `DataCard`) often use `onClick` handlers but lack native keyboard support. Users relying on keyboard navigation (like Tab) would bypass these critical content cards, missing out on core functionality like viewing item details.
**Action:** When applying `onClick` to non-button, generic container elements (like `div` or `motion.div`) to make them interactive, always pair it with `role="button"`, `tabIndex={0}` (conditionally based on actionability), an `onKeyDown` handler that triggers on `Enter` and `Space`, and `focus-visible` utility classes to ensure both keyboard reachability and visible focus state while respecting the design system.
