## 2026-06-22 - Dynamic Accessibility Semantics for Interactive Elements
**Learning:** When custom elements (like `motion.div` cards) have multiple states—such as an "edit mode" where the whole card becomes non-interactive while containing interactive sub-elements (like edit/delete buttons)—it's crucial to dynamically remove accessibility semantics (`role`, `tabIndex`, keyboard handlers) and focus styles. Leaving them on causes screen readers and keyboard users to encounter confusing, dead-end focus stops that trigger no action.
**Action:** Always conditionally bind `role="button"`, `tabIndex={0}`, `onKeyDown` handlers, and `focus-visible` utility classes to the active interactive state (e.g., `!editMode`), rendering them `undefined` or removing them when the element is inactive.
