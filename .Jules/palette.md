## 2026-05-23 - Adding Keyboard Accessibility to Non-Button Interactive Elements
**Learning:** In this application, elements like `motion.div` that serve as interactive cards (e.g., in `DataCard.tsx`) lack native keyboard accessibility. While an `onClick` handler exists, screen readers and keyboard-only users cannot interact with these elements without explicit roles, tab indices, and keyboard event handlers. This is a common pattern when using custom interactive containers.
**Action:** Always pair `onClick` handlers on non-button interactive elements with `role="button"`, `tabIndex={0}` (conditionally applied based on state), an `onKeyDown` handler to catch 'Enter' and 'Space' keys, and `focus-visible` utility classes to ensure a clear visual focus indicator for keyboard navigation.
