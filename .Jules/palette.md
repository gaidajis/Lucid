## 2024-06-17 - Keyboard Accessibility and State-Dependent Interactions in motion.div
**Learning:** Custom interactive elements built with `motion.div` do not inherently possess keyboard accessibility primitives (like `role`, `tabIndex`, or `onKeyDown`). Furthermore, they may improperly retain interactive styles (like `cursor-pointer` and hover effects) even when their interactivity is disabled by application state (e.g., `editMode`), leading to confusing user experiences.
**Action:** When creating interactive elements using non-native HTML elements (like `div` or `motion.div`), always conditionally apply `role="button"`, `tabIndex={0}`, `onKeyDown` handlers (specifically for 'Enter' and 'Space'), and interactive utility classes (`cursor-pointer`, `hover`, `focus-visible`) based on the element's actual active/interactive state.
