## 2024-06-19 - Conditional Accessibility Semantics on Interactive Cards
**Learning:** Components that switch between interactive (e.g., viewing details on click) and non-interactive/management states (e.g., edit mode where click actions are disabled) need to dynamically update their accessibility semantics. Leaving `role="button"`, `tabIndex={0}`, and `cursor-pointer` on a card while in edit mode creates false affordances for screen readers and keyboard users, leading to confusion when the interaction is disabled.
**Action:** When conditionally disabling click interactions on a component (like `DataCard` in `editMode`), ensure that all associated accessibility and interactive visual cues are also disabled. Use conditional rendering for `role`, `tabIndex`, `onKeyDown`, `cursor-pointer`, and `focus-visible` styles to match the interactive state precisely.
