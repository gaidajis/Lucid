## 2024-06-05 - Accessible `motion.div` Buttons with Dynamic Interactability
**Learning:** When using `motion.div` (or generic `div`s) with `onClick` handlers as interactive cards, they lack native keyboard accessibility. Furthermore, in apps where interactability is dynamic (like edit modes where the card itself shouldn't trigger its normal view action), leaving these semantics active creates a confusing experience for screen readers and keyboard users.
**Action:** Always pair `onClick` on non-button elements with `role="button"`, `tabIndex={0}`, an `onKeyDown` handler (for `Enter` and `Space`), and `focus-visible` styling. Crucially, when the element's interactability changes (e.g., in edit mode), dynamically remove these semantics (`role={undefined}`, `tabIndex={undefined}`, and remove the click/keydown handlers or prevent their execution) and also disable visual interactability cues like pointer cursors and hover effects.
