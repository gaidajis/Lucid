## 2024-06-30 - O(N) Array Grouping Memoization Pattern
**Learning:** In the `lucid` React application, filtering and grouping an array sequentially without memoization results in O(N * Tiers) operations on every component render. Since `App.tsx` handles frequent unrelated state updates, recalculating `itemsByTier` synchronously was creating unnecessary main thread work.
**Action:** Always memoize expensive array transformations (filtering/grouping) using `useMemo` in high-level components. Prefer a single O(N) pass to populate a pre-initialized accumulator map rather than relying on multiple `filter()` calls per category, to maintain optimal performance as data size grows. Ensure all dependencies (like static IDs or filter configuration) are included in the dependency array to pass strict linting rules.
