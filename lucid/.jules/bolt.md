## 2024-07-01 - Optimize Zustand Store Data Transformation
**Learning:** In the `lucid/` app architecture, components map over a static list of categories (`tierIds`) and sequentially `filter` the global Zustand `items` array for each category. With $N$ items and $T$ tiers, this pattern results in $O(N \times T)$ iterations on every render, causing significant performance bottlenecks during unrelated state updates since these transformations are not memoized.
**Action:** Always memoize expensive data transformations with `useMemo` in high-level components to prevent unnecessary re-renders. Furthermore, for array grouping and aggregation, prefer a single $O(N)$ pass using a lookup map (e.g., `reduce` with a pre-populated accumulator) rather than sequential $O(N)$ filter operations.
