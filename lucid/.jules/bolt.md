## 2024-07-04 - Memoizing Data Transformations and Grouping Optimizations
**Learning:** In the `lucid/` project, filtering and grouping the Zustand store's items array in high-level components without memoization causes performance bottlenecks during unrelated state updates. For array grouping/aggregation across multiple categories (like Tiers), running sequential `O(N * Tiers)` filter operations is inefficient.
**Action:** Always memoize expensive data transformations with `useMemo` in high-level components. For array grouping/aggregation, prefer a single `O(N)` pass using a lookup map (e.g., `reduce` with a pre-populated accumulator followed by a single `.forEach` over items) rather than sequential `O(N * Tiers)` filter operations. Also, explicitly include all referenced variables, including static arrays like `tierIds`, in the dependency array to pass strict code review checks.
