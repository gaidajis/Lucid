## 2024-07-04 - Keyboard Accessibility for Custom Interactive Elements
**Learning:** In the Lucid app, many `div` elements act as primary interaction points (e.g., DataCards opening modals). Simply adding `onClick` neglects keyboard users. Furthermore, when the app enters `editMode`, these cards should *not* be interactive for viewing. A critical pattern is conditionally applying full accessibility semantics (`role`, `tabIndex`, `onKeyDown`, and `focus-visible` styles) based on the application state, and critically, calling `e.preventDefault()` on the 'Space' key to stop default page scrolling when interacting with `role="button"` elements.
**Action:** When implementing `onClick` on non-button containers like `DataCard`, conditionally bind `role="button"`, `tabIndex={0}`, and handle `Enter`/`Space` (with `e.preventDefault()`). Remove these semantics and custom hover/focus styles entirely when the element is in a disabled or non-interactive state (like `editMode`).
