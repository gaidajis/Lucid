## 2024-05-18 - Disabled State Styling and Keyboard Semantics on Custom Elements
**Learning:** When turning non-button elements (like `motion.div`) into interactive components, it's crucial not only to add `role="button"` and `tabIndex`, but to also ensure that interactive styles (like `cursor-pointer`, hover effects, and `focus-visible` outlines) and keyboard access (`tabIndex` and `onKeyDown`) are dynamically removed when the element enters a non-interactive state (like an "edit mode"). Leaving pointer cursors or focus rings on elements that cannot be clicked causes confusion and violates accessibility best practices for disabled states.
**Action:** Always conditionally apply `cursor-pointer`, hover styles, `focus-visible` utilities, `tabIndex`, and `onKeyDown` handlers based on the element's interactive state (e.g., `!editMode` or `!disabled`). When mapping `onClick` to a `div`, strictly adhere to adding `role="button"`, `tabIndex`, and `Enter`/`Space` key support.
