## 2024-06-26 - Conditionally Interactive Non-Button Elements
**Learning:** When building list or grid items (like DataCard) that are clickable in default view but become non-interactive containers in edit mode, they can cause a confusing UX if they retain their interactive styling (like pointer cursors) and semantics. Removing keyboard focus and role when they are functionally disabled prevents screen readers from announcing them as buttons and avoids tab-traps.
**Action:** When converting non-button elements (like `div` or `motion.div`) into interactive elements using `onClick`, always conditionally apply `role="button"`, `tabIndex={0}`, `onKeyDown` handlers (for Enter/Space), and interactive styles (hover shadows, `cursor-pointer`, `focus-visible` outlines) based on whether the element is actually interactive in the current application state (e.g., `!editMode`).
