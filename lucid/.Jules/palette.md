## 2024-08-15 - Conditionally Interactive Elements and Accessibility Semantics
**Learning:** When elements (like cards) change state from being interactive buttons to non-interactive displays (e.g., in an "Edit Mode"), leaving pointer cursors, hover effects, and keyboard navigation semantics (`tabIndex`, `role="button"`) active on the wrapper can create a confusing experience, especially for keyboard and screen reader users who expect an action to occur upon interaction.
**Action:** When designing conditionally interactive elements, dynamically remove or apply interactive semantics (`role="button"`, `tabIndex={0}`, `onKeyDown`), styling (hover effects, cursor types), and focus states (`focus-visible`) based on the active state. Do not rely solely on disabling the click handler (`onClick`), as the element will still appear interactive to assistive technologies and keyboard navigation.
