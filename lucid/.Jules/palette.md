## 2024-06-27 - Conditionally Interactive Containers
**Learning:** When container elements like `motion.div` function as buttons in read-only mode but switch to being purely structural containers in edit mode, they must dynamically toggle their interactive semantics (`role="button"`, `tabIndex`, `onKeyDown`) and visual cues (cursor, hover effects, focus rings) to match the current state. Otherwise, users might mistakenly try to interact with them in edit mode, leading to confusion or inaccessible behavior.
**Action:** Always wrap interactive containers with a keyboard event handler for `Enter` and `Space` (preventing default scrolling for Space), apply `focus-visible` styles, and ensure all interactive semantics and visual cues are explicitly removed (`tabIndex={-1}`, `role={undefined}`, no pointer cursor, etc.) when the component enters a disabled or non-interactive state.
