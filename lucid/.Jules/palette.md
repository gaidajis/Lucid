## 2024-07-01 - Conditional Accessibility on Interactive Framer Motion Elements
**Learning:** When using `motion.div` as an interactive element (acting as a button), it requires standard accessibility properties (`role="button"`, `tabIndex={0}`, `onKeyDown` handlers for Enter/Space, and visible focus states). Crucially, these properties must be dynamically removed or set to `undefined` when the element's interactive state is disabled (e.g., when the app enters an "edit mode" where the click handler is bypassed and other internal controls become active) to prevent screen readers and keyboard users from interacting with a conceptually disabled element.
**Action:** When implementing clickable `motion.div` or `div` elements, always apply `role="button"`, `tabIndex`, keyboard event handlers, and `focus-visible` styles. If the element's interactivity is conditional, ensure all of these accessibility attributes are conditionally applied or stripped along with the visual interactive cues (like `cursor-pointer`).
