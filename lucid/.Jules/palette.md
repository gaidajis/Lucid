## 2024-06-19 - Keyboard Accessibility for Non-Button Elements (motion.div)
**Learning:** For interactive non-button elements (like `div` or `motion.div` acting as cards), keyboard accessibility is incomplete with just an `onClick` handler. It requires pairing with `role="button"`, `tabIndex={0}`, an `onKeyDown` handler that specifically checks for `Enter` or `Space` (and calls `e.preventDefault()`), and visual focus outlines (`focus-visible` classes). Furthermore, when interactive elements enter a non-interactive mode (e.g. edit mode disables clicking on the main card), all of these accessibility semantics (`role`, `tabIndex`, `onKeyDown`, pointer styles, and focus styles) must be completely disabled or removed to avoid confusing screen readers and keyboard navigation users.
**Action:** Always conditionally apply `tabIndex`, `role`, `onKeyDown`, and `focus-visible` classes on interactive non-button elements, strictly matching their interactive state (`!editMode`).
