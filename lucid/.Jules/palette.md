## 2025-02-24 - Conditional Accessibility Semantics
**Learning:** Screen readers and keyboard navigation can be confused when a container element (like a card) has an `onClick` handler but acts as a passive container for child buttons (like Edit/Delete) during a specific state (e.g. `editMode`). If `role="button"` and `tabIndex={0}` remain active on the parent, users tab to the parent and expect interaction, even though it's disabled or shadowed by children.
**Action:** When a UI component switches between acting as an interactive button itself (e.g., viewing details) and acting as a non-interactive container for other actions (e.g., edit mode), dynamically remove `role`, `tabIndex`, interactive styling (cursor, hover states), and keyboard event handlers by setting them to `undefined` or conditionally omitting them to prevent confusing keyboard/screen reader experiences.
