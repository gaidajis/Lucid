## 2024-07-03 - Dynamic Keyboard Semantics on Toggleable Interactive Elements
**Learning:** When interactive elements (like DataCard) toggle between clickable and non-interactive states (e.g. entering an edit mode where only sub-buttons are clickable), simply removing the onClick handler isn't enough. Screen readers and keyboard users will still perceive the element as interactive if structural semantics (role, tabIndex, hover shadows) remain. It causes confusion when focus lands on an element that no longer performs an action.
**Action:** When a component's primary interaction is disabled dynamically, conditionally remove its pointer cursor, hover effects, `role="button"`, `tabIndex`, and `onKeyDown` handlers so it gracefully degrades to a static element in the accessibility tree.
