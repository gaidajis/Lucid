## 2024-08-11 - Dynamic Semantics for Clickable Cards in Edit Modes
**Learning:** When a generic wrapper element (like `motion.div`) acts as a primary clickable card in viewing mode, it requires full `button` semantics (role, tabIndex, onKeyDown) for accessibility. However, if the UI transitions into an "edit mode" where the card itself is no longer intended to be clickable (e.g., clicks are delegated to inner edit/delete icon buttons), leaving those button semantics on the wrapper creates confusion for screen reader and keyboard users (they focus a "button" that doesn't do anything).
**Action:** Conditionally apply accessibility properties (`role="button"`, `tabIndex={0}`, `onKeyDown`, and `focus-visible` styles) based on the current mode (e.g., `!editMode`), ensuring the element completely drops from the focus order and loses button semantics when not interactive.
