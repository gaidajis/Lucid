## 2024-06-10 - Dynamic Accessibility for Mode-Dependent Elements
**Learning:** When interactive elements (like cards that open modals) switch to a state where their primary interaction is disabled (e.g., entering an "edit mode" where overlay buttons appear instead), retaining pointer cursors, hover effects, and keyboard focus creates confusing affordances. Screen readers and keyboard users will land on the element expecting interaction, only to find it unresponsive.
**Action:** Always conditionally render accessibility semantics (`role`, `tabIndex`, `onKeyDown`) and interactive visual cues (`cursor-pointer`, hover styling, `focus-visible` rings) based on the element's current interactive state. If an element is functionally disabled in a specific mode, its accessibility attributes and hover states should be completely removed.
