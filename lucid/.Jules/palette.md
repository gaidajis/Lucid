## 2025-02-28 - Conditional Accessibility for Custom Interactive Elements
**Learning:** When making non-standard HTML elements (like `div` or `motion.div`) interactive and act as buttons, keyboard accessibility semantics (`role`, `tabIndex`, and `onKeyDown`) and styles (`cursor-pointer`, `focus-visible`, `hover`) should only be applied when the element is actually in an interactive state. If a card acts as a button but interactions are disabled during 'edit mode', leaving `role="button"` and `tabIndex={0}` creates a broken experience for screen readers and keyboard users as they can focus elements they cannot interact with. Additionally, `e.preventDefault()` must be called explicitly when handling the 'Space' key via `onKeyDown` to prevent the browser's default behavior of scrolling the page.
**Action:** Always conditionally apply `role`, `tabIndex`, and interactive styles (like `focus-visible`) based on the component's actual interactive state. Ensure `onKeyDown` correctly handles 'Enter' and 'Space' with appropriate `e.preventDefault()` calls for custom interactive elements.
