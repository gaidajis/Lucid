## 2024-05-24 - Interactive Card Accessibility
**Learning:** Custom non-button elements (like `div` or `motion.div`) acting as interactive cards need explicit keyboard accessibility (`role="button"`, `tabIndex={0}`, `onKeyDown` with `Enter`/`Space` support, and `focus-visible` styles) to be usable by keyboard users, and these attributes must be dynamically disabled when the card enters a non-interactive state (like an edit mode) to prevent confusing focus order.
**Action:** Always pair `onClick` on non-button elements with `role="button"`, `tabIndex={0}`, an `onKeyDown` handler (calling `e.preventDefault()` for `Space`), and `focus-visible` utility classes (e.g., `focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-black dark:focus-visible:ring-white`), ensuring these attributes are conditionally applied based on the element's interactive state.
