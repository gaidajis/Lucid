## 2024-06-05 - Conditionally Disable Interactive Semantics in Edit Modes
**Learning:** When interactive elements (like data cards) lose their primary interactivity during specific app states (e.g., entering an "Edit Mode" where the card itself is no longer clickable to view details, but instead surfaces internal edit/delete buttons), simply checking the state in the `onClick` handler is insufficient for good UX and accessibility. Keeping pointer cursors, hover shadows, and keyboard focus semantics active misleads users into thinking the entire element is still interactive.
**Action:** Always conditionally disable pointer cursors, hover effects, `focus-visible` outlines, and keyboard accessibility semantics (`tabIndex`, `role`, `onKeyDown`) on elements when they are placed into a disabled or non-interactive state.
