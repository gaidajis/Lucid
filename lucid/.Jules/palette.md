## 2024-08-11 - Dynamic Keyboard Semantics for Mode-Switching Elements
**Learning:** When elements like `DataCard` switch modes (e.g., entering an `editMode` where clicking the card no longer triggers the main view action, but rather reveals internal edit/delete buttons), leaving `role="button"`, `tabIndex`, and `onKeyDown` active can cause confusion for keyboard and screen reader users. The element appears interactive but no longer responds to the expected actions.
**Action:** Dynamically remove keyboard semantics (`role={editMode ? undefined : 'button'}`, `tabIndex={editMode ? undefined : 0}`) and bypass `onKeyDown` logic when the element is placed into a non-interactive mode. Additionally, ensure focus-visible utility classes (`focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-black dark:focus-visible:ring-white`) are applied only when the element is interactive.
