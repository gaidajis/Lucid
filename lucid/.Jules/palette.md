## 2024-11-20 - DataCard Keyboard Accessibility
**Learning:** The application uses framer-motion `<motion.div>` elements as interactive card components (DataCard). When these act as buttons via `onClick` events, they lack native keyboard accessibility, roles, and focus styles, trapping keyboard users out of core functionality. Additionally, these cards continue to look clickable even when interactions are blocked (e.g., during edit mode).
**Action:** When implementing click handlers on non-native button elements (like cards), always pair them with `role="button"`, `tabIndex={0}`, an `onKeyDown` handler (for `Enter` and `Space`, calling `e.preventDefault()` on `Space` to avoid scrolling), and `focus-visible` styling. Ensure interactive visual states (cursor, hover shadow) are disabled when the element is functionally unclickable.
