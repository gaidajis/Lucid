## 2024-03-24 - Conditional Accessibility for Interactive Cards
**Learning:** When making non-button elements (like cards) interactive and keyboard accessible, it's crucial to remove accessibility semantics (like `role`, `tabIndex`, and keyboard event handlers) when the component enters a disabled or edit state to prevent false affordances for screen readers and keyboard users. Additionally, when mapping the `Space` key to activate a card, `e.preventDefault()` must be explicitly called to stop the default browser behavior of scrolling the page.
**Action:** When implementing custom interactive elements, always conditionally apply `role`, `tabIndex`, keyboard listeners, and `focus-visible` styles based on the interactive state (e.g., `!editMode`). Always prevent default scrolling on the `Space` key when it is used to trigger an action.
