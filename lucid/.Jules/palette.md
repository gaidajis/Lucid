## 2024-07-08 - Contextual Accessibility of Interactive Elements
**Learning:** In applications with distinct modes (like a global Edit vs. View mode), elements that serve as interactive buttons in one mode may become static display components in another. Keeping them inherently interactive (with default focus states, pointer cursors, and keyboard semantics) during edit mode can lead to confused screen readers and misaligned user expectations if the click action is disabled but the semantics are not.
**Action:** Always conditionally apply `role="button"`, `tabIndex`, keyboard event handlers (`onKeyDown`), and visual interactive cues (like `cursor-pointer`, hover effects, and `focus-visible` styling) based on the application state that determines interactivity, explicitly disabling these traits when the element shouldn't be interacted with.
