## 2025-01-28 - Dynamic Interactive Elements and Accessibility Semantics
**Learning:** Interactive elements (like `<motion.div>` used as a card) that have their interactivity dynamically enabled/disabled (e.g., via an `editMode` toggle where clicking is only valid when not in edit mode) need more than just conditionally applying `cursor-pointer`. All associated accessibility semantics—including `role="button"`, `tabIndex`, keyboard event handlers (`onKeyDown`), and visual focus rings—must be disabled simultaneously when the element ceases to be interactive to prevent screen readers and keyboard users from encountering confusing, non-functional states.
**Action:** When conditionally enabling interactivity on non-native interactive elements (like `div`), group the `role`, `tabIndex`, `onKeyDown`, and styling modifications (cursor and focus ring) together under the same boolean condition to ensure a consistent accessibility tree state.
