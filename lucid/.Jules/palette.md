## 2024-06-12 - Keyboard Accessibility for Non-Button Elements
**Learning:** In the Lucid app, many interactive elements are constructed using generic `div` or `motion.div` containers (e.g., `DataCard`). While these have `onClick` handlers for mouse users, they completely lack accessibility semantics, making them invisible and inaccessible to keyboard users navigating via `Tab` or screen readers. Furthermore, the interactivity of these elements changes dynamically based on the app's state (like `editMode`).
**Action:** When adding `onClick` to non-button elements, always pair it with `role="button"`, `tabIndex={0}`, an `onKeyDown` handler (listening for `Enter` and `Space`), and proper `focus-visible` utility classes (`focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-black dark:focus-visible:ring-white`). Crucially, these attributes and focus styles must be conditionally disabled when the element is placed into a non-interactive state (e.g., when `editMode` is active).
