## 2024-07-07 - Dynamic Interactive States and Accessibility
**Learning:** When interactive elements (like `motion.div` acting as buttons) become disabled or non-interactive based on application state (e.g., entering "edit mode"), leaving static interaction semantics (`role="button"`, `tabIndex={0}`, hover styles, and pointer cursors) creates a confusing experience for both keyboard and mouse users. Screen readers announce them as buttons, and hover styles suggest interactivity, but clicks do nothing.
**Action:** Always bind accessibility semantics (`role`, `tabIndex`, `onKeyDown`) and visual interactive hints (cursors, hover effects, focus rings) to the same condition that governs the actual click handler (`onClick`). Conditionally apply these properties (e.g., `role={!disabled ? "button" : undefined}`) so the element correctly degrades to a non-interactive state.
