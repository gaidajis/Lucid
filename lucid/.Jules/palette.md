## 2024-08-14 - Interactive Card Keyboard Accessibility in Edit States
**Learning:** When making non-button elements (like `motion.div`) interactive, simply adding `onClick` isn't enough for accessibility. They need `role="button"`, `tabIndex={0}`, and `onKeyDown` handlers to support keyboard users. Furthermore, when these elements have different interactive states (like a view mode vs an edit mode where inner buttons take precedence), these accessibility attributes and focus styles must be conditionally disabled to prevent confusing tab orders and misleading semantics.
**Action:** When implementing interactive cards that change behavior based on a global state (like `editMode`), ensure all keyboard accessibility semantics (`role`, `tabIndex`, `onKeyDown`, `focus-visible`, `cursor-pointer`) are conditionally applied only when the element is actually meant to be interactive in that specific state.
